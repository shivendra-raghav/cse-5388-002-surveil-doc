Object Storage Endpoint
-----------------------
The base endpoint for accessing Vultr Object Storage is `https://obj.vultr.com`. This endpoint is used for uploading, downloading, and managing objects within your Object Storage buckets.

Multi-part Uploads
==================

Large Object Uploads
--------------------
Vultr Object Storage supports multi-part uploads, which allow you to upload large objects in smaller, manageable parts. This feature is particularly useful when uploading objects larger than a few gigabytes, as it provides better reliability, restartability, and performance.

To initiate a multi-part upload, you need to send an HTTP request to the Object Storage endpoint with the appropriate headers and request body. Here's an example using the AWS CLI:

```
aws s3 create-multipart-upload --bucket my-bucket --key my-large-object.zip
```

This command returns an upload ID, which you'll need to use for subsequent upload part requests.

Uploading Parts
---------------
After initiating a multi-part upload, you can start uploading individual parts of the object. Each part must be between 5 MB and 5 GB in size, except for the last part, which can be smaller.

To upload a part, you'll need to send an HTTP request with the appropriate headers and the part data as the request body. Here's an example using the AWS CLI:

```
aws s3 upload-part --bucket my-bucket --key my-large-object.zip --part-number 1 --upload-id <UPLOAD_ID> --body-file part1.zip
```

Replace `<UPLOAD_ID>` with the upload ID you received from the `create-multipart-upload` command.

Completing the Upload
---------------------
After uploading all the parts, you need to complete the multi-part upload by sending a request with the list of uploaded parts and their respective part numbers. Here's an example using the AWS CLI:

```
aws s3 complete-multipart-upload --bucket my-bucket --key my-large-object.zip --upload-id <UPLOAD_ID> --multipart-upload "Parts=[{ETag=etag1, PartNumber=1},{ETag=etag2, PartNumber=2}]"
```

Replace `<UPLOAD_ID>` with the actual upload ID, and provide the appropriate part numbers and ETag values for each part you uploaded.

Object Metadata
===============

Storing and Retrieving Metadata
-------------------------------
Vultr Object Storage allows you to store and retrieve metadata associated with your objects. Metadata can be useful for various purposes, such as storing object descriptions, tags, or any other custom information you need.

To store metadata when uploading an object, you can use the `--metadata` option with the AWS CLI. For example:

```
aws s3 cp my-file.txt s3://my-bucket/my-file.txt --metadata key1=value1,key2=value2
```

This command uploads the file `my-file.txt` to the `my-bucket` bucket and associates the metadata keys `key1` and `key2` with the values `value1` and `value2`, respectively.

To retrieve metadata for an object, you can use the `--metadata` option with the AWS CLI's `head-object` command. For example:

```
aws s3 head-object --bucket my-bucket --key my-file.txt --metadata
```

This command retrieves the metadata associated with the `my-file.txt` object in the `my-bucket` bucket.

System-Defined Metadata
-----------------------
In addition to user-defined metadata, Vultr Object Storage also provides system-defined metadata for each object. This metadata includes information such as the object's size, content type, and last modified date.

To retrieve system-defined metadata for an object, you can use the AWS CLI's `head-object` command without the `--metadata` option. For example:

```
aws s3 head-object --bucket my-bucket --key my-file.txt
```

This command retrieves the system-defined metadata for the `my-file.txt` object in the `my-bucket` bucket.
