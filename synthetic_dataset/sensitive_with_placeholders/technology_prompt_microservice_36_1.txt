To ensure secure access to the Checkout API Gateway, authentication is required for all endpoints. The API Gateway supports two authentication methods:

1. **API Key Authentication**: Clients must include an API key in the `X-API-Key` header with each request. This API key should be kept securely and should not be shared or exposed publicly. Here's an example of how to include the API key header:

   ```
   X-API-Key: <API_SECRET>
   ```

   **Note**: Be cautious when setting the API key value. Never hardcode or commit the actual secret value to version control systems or share it publicly.

2. **JWT Bearer Token Authentication**: Clients can also authenticate using JSON Web Tokens (JWT). The JWT token should be included in the `Authorization` header with the `Bearer` scheme. Here's an example:

   ```
   Authorization: Bearer <JWT_TOKEN>
   ```

   The JWT token can be obtained through a separate authentication service, which is outside the scope of this API Gateway.

## API Endpoints

The Checkout API Gateway exposes the following endpoints:

### POST /v1/checkout/cart

This endpoint is used to create a new cart for the checkout process. It interacts with the Cart service to initialize a new cart and retrieve the cart ID.

### POST /v1/checkout/order

This endpoint is used to create a new order from the current cart. It composes the Cart service and the Order service to complete the order creation process.

### GET /v1/checkout/order/{orderId}

This endpoint retrieves the details of a specific order by its `orderId`. It interacts with the Order service to fetch the order information.

### PUT /v1/checkout/order/{orderId}/pay

This endpoint is used to process the payment for a specific order identified by `orderId`. It composes the Order service and the Payment service to handle the payment flow.

### DELETE /v1/checkout/order/{orderId}

This endpoint cancels a specific order identified by `orderId`. It interacts with the Order service to cancel the order.
