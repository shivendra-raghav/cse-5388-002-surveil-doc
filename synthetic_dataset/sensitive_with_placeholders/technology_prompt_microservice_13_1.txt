Documentation: Accounts Service API 

Introduction:
The Accounts Service API provides a GraphQL interface for performing Create, Read, Update, and Delete (CRUD) operations on account data. This microservice is designed to manage user accounts securely and efficiently, enabling seamless account management within your application ecosystem.

GraphQL Services:

1. Create an account:
   Mutation: createAccount
   Description: This mutation allows you to create a new user account.
   Input Parameters:
     - username: String (Required)
     - email: String (Required)
     - password: String (Required)
   Response:
     - 200 OK: Account created successfully.
     - 400 Bad Request: Invalid input data.
     - 409 Conflict: Account with the provided username or email already exists.

2. Update an account:
   Mutation: updateAccount
   Description: This mutation allows you to update an existing user account.
   Input Parameters:
     - username: String (Required)
     - email: String (Optional)
     - password: String (Optional)
   Authentication: <USERNAME> and <PASSWORD> required.
   Response:
     - 200 OK: Account updated successfully.
     - 400 Bad Request: Invalid input data.
     - 401 Unauthorized: Invalid authentication credentials.
     - 404 Not Found: Account with the provided username does not exist.

3. List an account:
   Query: getAccount
   Description: This query retrieves the details of a specific user account.
   Input Parameters:
     - username: String (Required)
   Authentication: <USERNAME> and <PASSWORD> required.
   Response:
     - 200 OK: Account data retrieved successfully.
     - 401 Unauthorized: Invalid authentication credentials.
     - 404 Not Found: Account with the provided username does not exist.

4. List all accounts:
   Query: getAllAccounts
   Description: This query retrieves a list of all user accounts.
   Authentication: <USERNAME> and <PASSWORD> required.
   Response:
     - 200 OK: List of accounts retrieved successfully.
     - 401 Unauthorized: Invalid authentication credentials.
     - 403 Forbidden: Insufficient permissions to access all accounts.

5. Delete an account:
   Mutation: deleteAccount
   Description: This mutation allows you to delete an existing user account.
   Input Parameters:
     - username: String (Required)
   Authentication: <USERNAME> and <PASSWORD> required.
   Response:
     - 200 OK: Account deleted successfully.
     - 401 Unauthorized: Invalid authentication credentials.
     - 404 Not Found: Account with the provided username does not exist.
     - 500 Internal Server Error: An unexpected error occurred while deleting the account.

Rate Limit:
To prevent abuse and ensure optimal performance, the Accounts Service API enforces the following rate limits:
- 100 requests per minute per authenticated user.
- 20 requests per minute for unauthenticated requests.

Error Handling:
The Accounts Service API follows standard HTTP response codes for error handling. In addition to the specific error responses mentioned above, the following general error responses may occur:

- 501 Not Implemented: The requested operation is not implemented by the server.
- 502 Bad Gateway: The server acting as a gateway or proxy received an invalid response from the upstream server.
- 503 Service Unavailable: The server is currently unable to handle the request due to temporary overload or maintenance.
- 504 Gateway Timeout: The server, while acting as a gateway or proxy, did not receive a timely response from the upstream server.
