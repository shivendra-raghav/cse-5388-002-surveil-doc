# Payments Service GraphQL API Documentation

## Introduction

The Payments Service is a microservice that enables Create, Read, Update, and Delete (CRUD) operations for managing payments within an application. This service is designed to handle various payment-related functionalities, including creating new payments, updating existing payments, retrieving payment details, listing all payments, and deleting payments.

## GraphQL Services

The Payments Service exposes the following GraphQL APIs:

### 1. Create a Payment

This API allows you to create a new payment record.

**Endpoint:** `/graphql`

**Method:** POST

**Query:**

```graphql
mutation createPayment($input: CreatePaymentInput!) {
  createPayment(input: $input) {
    id
    amount
    currency
    status
    createdAt
    updatedAt
  }
}
```

**Input:**

```graphql
input CreatePaymentInput {
  amount: Float!
  currency: String!
  paymentMethod: String!
  customerId: ID!
}
```

**Responses:**

- 200 OK: The payment was created successfully.
- 400 Bad Request: The request data is invalid or incomplete.
- 401 Unauthorized: Authentication failed. You must provide a valid <API_TOKEN> or <OAUTH_ID> to access this API.
- 500 Internal Server Error: An unexpected error occurred on the server.

### 2. Update a Payment

This API allows you to update an existing payment record.

**Endpoint:** `/graphql`

**Method:** POST

**Query:**

```graphql
mutation updatePayment($id: ID!, $input: UpdatePaymentInput!) {
  updatePayment(id: $id, input: $input) {
    id
    amount
    currency
    status
    updatedAt
  }
}
```

**Input:**

```graphql
input UpdatePaymentInput {
  amount: Float
  currency: String
  status: String
}
```

**Responses:**

- 200 OK: The payment was updated successfully.
- 400 Bad Request: The request data is invalid or incomplete.
- 401 Unauthorized: Authentication failed. You must provide a valid <API_TOKEN> or <OAUTH_ID> to access this API.
- 404 Not Found: The payment with the specified ID was not found.
- 500 Internal Server Error: An unexpected error occurred on the server.

## Rate Limit

The Payments Service has a rate limit of 100 requests per minute per client. If you exceed this limit, you will receive a 429 Too Many Requests response. The rate limit is enforced to prevent abuse and ensure fair usage of the service.

## Error Handling

The Payments Service follows standard HTTP response codes for error handling:

- 400 Bad Request: The request data is invalid or incomplete.
- 401 Unauthorized: Authentication failed.
- 403 Forbidden: The client does not have permission to access the requested resource.
- 404 Not Found: The requested resource was not found.
- 500 Internal Server Error: An unexpected error occurred on the server.
- 501 Not Implemented: The requested functionality is not implemented.
- 502 Bad Gateway: The server received an invalid response from an upstream server.
- 503 Service Unavailable: The server is currently unavailable due to maintenance or overload.
- 504 Gateway Timeout: The server did not receive a timely response from an upstream server.
