## Backup Details

Azure SQL Database provides built-in backup capabilities to protect against data loss and enable recovery in case of an outage or disaster. Backups are automatically created and maintained by the Azure SQL service, ensuring that your data is protected and can be restored when needed.

### Automated Backups
Azure SQL Database automatically creates full, differential, and transaction log backups at regular intervals. These backups are stored in geo-replicated blob storage and are available for restore operations within the specified retention period.

- **Full Backups**: Full backups are created weekly and retained for 35 days.
- **Differential Backups**: Differential backups are created every 12 hours and retained for 35 days.
- **Transaction Log Backups**: Transaction log backups are created every 5-10 minutes and retained for 35 days.

### Point-in-Time Restore
Azure SQL Database allows you to restore a database to a specific point in time within the retention period. This feature is useful for recovering from accidental data modifications, logical errors, or other scenarios where you need to revert to a previous state of the database.

## Database Details

### Database Naming Convention
Our Azure SQL Databases follow a consistent naming convention to ensure organization and easy identification. The naming convention is as follows:

`<Application_Name>_<Environment>_<Database_Type>`

For example: `SalesApp_Dev_Main`, `InventoryApp_QA_Reporting`, `HRApp_Prod_Staging`.

### Database Schemas
Each Azure SQL Database instance consists of several schemas to logically organize and manage database objects. The commonly used schemas and their purposes are:

- `dbo`: The default schema for storing application-related tables, views, stored procedures, and functions.
- `audit`: This schema is dedicated to storing audit logs and tracking changes made to the database.
- `reporting`: This schema houses views and stored procedures specifically designed for reporting purposes.
