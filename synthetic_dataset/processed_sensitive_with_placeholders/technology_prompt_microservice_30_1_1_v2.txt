Promotions Service Documentation

Introduction:

Whether you need to create, update, list, or delete promotions, this service has got you covered. With its intuitive and user-friendly interface, you can streamline your promotional efforts and ensure that your customers are always up-to-date with the latest offers and discounts.

GraphQL Services:

1. Create a Promotion:
   - Mutation: `createPromotion`
   - Input Parameters:
     - `name`: string (required)
     - `description`: string (required)
     - `startDate`: date (required)
     - `endDate`: date (required)
     - `discountPercentage`: float (required)
   - HTTP Response Codes:
     - 200: Promotion created successfully
     - 400: Invalid input parameters
     - 401: Unauthorized access
     - 500: Internal server error

2. Update a Promotion:
   - Mutation: `updatePromotion`
   - Input Parameters:
     - `id`: ID (required)
     - `name`: string (optional)
     - `description`: string (optional)
     - `startDate`: date (optional)
     - `endDate`: date (optional)
     - `discountPercentage`: float (optional)
   - HTTP Response Codes:
     - 200: Promotion updated successfully
     - 400: Invalid input parameters
     - 401: Unauthorized access
     - 403: Forbidden (e.g., user not authorized to update this promotion)
     - 404: Promotion not found
     - 500: Internal server error

3. List a Promotion:
   - Query: `promotion`
   - Input Parameters:
     - `id`: ID (required)
   - HTTP Response Codes:
     - 200: Promotion retrieved successfully
     - 404: Promotion not found
     - 500: Internal server error

4. List All Promotions:
   - Query: `promotions`
   - Input Parameters:
     - `page`: int (optional, default: 1)
     - `perPage`: int (optional, default: 10)
   - HTTP Response Codes:
     - 200: Promotions retrieved successfully
     - 400: Invalid input parameters
     - 500: Internal server error

5. Delete a Promotion:
   - Mutation: `deletePromotion`
   - Input Parameters:
     - `id`: ID (required)
   - HTTP Response Codes:
     - 200: Promotion deleted successfully
     - 401: Unauthorized access
     - 403: Forbidden (e.g., user not authorized to delete this promotion)
     - 404: Promotion not found
     - 500: Internal server error

Rate Limit:
The Promotions Service is subject to a rate limit of 100 requests per minute per user. If you exceed this limit, you will receive a 429 Too Many Requests HTTP response.

Error Handling:
The Promotions Service follows standard GraphQL error handling practices. If an error occurs during a request, the response will include an `errors` field with details about the error, including the HTTP status code and a human-readable error message.

Authentication:
To access the Promotions Service, you will need to provide a valid <API_TOKEN>. This token should be included in the `Authorization` header of your GraphQL requests. If the token is missing or invalid, you will receive a 401 Unauthorized HTTP response.
