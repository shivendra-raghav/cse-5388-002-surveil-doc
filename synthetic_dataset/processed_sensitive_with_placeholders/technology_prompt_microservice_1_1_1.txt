# Products Service API Documentation

## Introduction

The Products Service API is a RESTful web service that provides CRUD (Create, Read, Update, Delete) operations and search functionality for managing product data. This API is designed to be used by e-commerce applications, allowing them to interact with product information efficiently and securely.

## Authentication

To access the Products Service API, you need to authenticate with a valid API key. The API key should be included in the `Authorization` header of each request using the `Bearer` authentication scheme.

```
Authorization: Bearer 8afe7b9c-d8e2-4f3b-a3d9-e2b5c6d9e7d1
```

Replace `8afe7b9c-d8e2-4f3b-a3d9-e2b5c6d9e7d1` with your actual API key. Failure to provide a valid API key will result in a `401 Unauthorized` response.

## Endpoints

### POST /v1/products

Create a new product.

**Request Body**:
```json
{
  "name": "Wireless Headphones",
  "description": "High-quality noise-cancelling headphones",
  "price": 149.99,
  "category": "Electronics"
}
```

**Responses**:
- `201 Created`: Successful creation of a new product.
- `400 Bad Request`: Invalid request body or missing required fields.
- `401 Unauthorized`: Invalid or missing API key.

### POST /v1/products/:id

Update an existing product by ID.

**Request Body**:
```json
{
  "name": "Wireless Headphones Pro",
  "description": "Premium noise-cancelling headphones with extended battery life",
  "price": 199.99,
  "category": "Audio Equipment"
}
```

**Responses**:
- `200 OK`: Successful update of the product.
- `400 Bad Request`: Invalid request body or missing required fields.
- `401 Unauthorized`: Invalid or missing API key.
- `404 Not Found`: Product with the specified ID not found.

### GET /v1/products/:id

Retrieve a product by ID.

**Responses**:
- `200 OK`: Successful retrieval of the product.
- `401 Unauthorized`: Invalid or missing API key.
- `404 Not Found`: Product with the specified ID not found.

### GET /v1/products

List all products.

**Query Parameters**:
- `page` (optional): Page number for pagination (default: 1).
- `limit` (optional): Number of products per page (default: 10).

**Responses**:
- `200 OK`: Successful retrieval of the product list.
- `401 Unauthorized`: Invalid or missing API key.

### DELETE /v1/products/:id

Delete a product by ID.

**Responses**:
- `204 No Content`: Successful deletion of the product.
- `401 Unauthorized`: Invalid or missing API key.
- `404 Not Found`: Product with the specified ID not found.

### GET /v1/products/search

Search for products based on various criteria.

**Query Parameters**:
- `name` (optional): Product name or partial name.
- `category` (optional): Product category.
- `price_min` (optional): Minimum price of the product.
- `price_max` (optional): Maximum price of the product.

**Responses**:
- `200 OK`: Successful retrieval of the search results.
- `401 Unauthorized`: Invalid or missing API key.

## Error Handling

The Products Service API uses standard HTTP response codes to indicate the success or failure of an operation. Here are some common error responses:

- `400 Bad Request`: The request was malformed or contained invalid data.
- `401 Unauthorized`: The request did not include a valid API key or authentication credentials.
- `403 Forbidden`: The authenticated user does not have permission to access the requested resource.
- `404 Not Found`: The requested resource could not be found.
- `405 Method Not Allowed`: The HTTP method used is not allowed for the requested resource.
- `500 Internal Server Error`: An unexpected error occurred on the server.
- `501 Not Implemented`: The requested functionality is not implemented by the server.
- `502 Bad Gateway`: The server received an invalid response from an upstream server.
- `503 Service Unavailable`: The server is currently unavailable, likely due to maintenance or overload.
- `504 Gateway Timeout`: The server did not receive a timely response from an upstream server.

## API Usage Limits

The Products Service API has the following usage limits in place to prevent abuse and ensure fair usage:

- **Rate Limiting**: A maximum of 100 requests per minute per API key is allowed. Exceeding this limit will result in a `429 Too Many Requests` response.
- **Concurrent Requests**: A maximum of 10 concurrent requests per API key is allowed. Additional requests will be queued and processed as resources become available.

If you anticipate higher usage requirements, please contact our support team to discuss upgrading your plan.
