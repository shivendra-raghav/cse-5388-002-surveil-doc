Accounts Service API Documentation

Introduction
The Accounts Service is a microservice that enables CRUD (Create, Read, Update, Delete) operations for managing user accounts. This service provides a simple and secure way to interact with the account data, allowing developers to build applications that require user authentication and account management functionality.

REST Services
The Accounts Service exposes the following REST API endpoints:

1. Create an Account
   - Endpoint: POST /accounts
   - Description: Creates a new user account.
   - Request Body:
     - `username` (string, required)
     - `email` (string, required, valid email format)
     - `password` (string, required, minimum 8 characters)
   - Responses:
     - 201 Created: Successfully created a new account.
     - 400 Bad Request: Invalid request body or missing required parameters.
     - 409 Conflict: Account with the provided email already exists.
     - 500 Internal Server Error: An unexpected error occurred on the server.

2. Update an Account
   - Endpoint: PUT /accounts/{accountId}
   - Description: Updates an existing user account.
   - Path Parameters:
     - `accountId` (string, required): The unique identifier of the account to be updated.
   - Request Body:
     - `username` (string, optional)
     - `email` (string, optional, valid email format)
     - `password` (string, optional, minimum 8 characters)
   - Responses:
     - 200 OK: Successfully updated the account.
     - 400 Bad Request: Invalid request body or missing required parameters.
     - 401 Unauthorized: Authentication is required to access this resource.
     - 403 Forbidden: You do not have permission to update the account.
     - 404 Not Found: The specified account does not exist.
     - 500 Internal Server Error: An unexpected error occurred on the server.

3. Get an Account
   - Endpoint: GET /accounts/{accountId}
   - Description: Retrieves the details of a specific user account.
   - Path Parameters:
     - `accountId` (string, required): The unique identifier of the account to be retrieved.
   - Responses:
     - 200 OK: Successfully retrieved the account details.
     - 401 Unauthorized: Authentication is required to access this resource.
     - 403 Forbidden: You do not have permission to access the account.
     - 404 Not Found: The specified account does not exist.
     - 500 Internal Server Error: An unexpected error occurred on the server.

4. List Accounts
   - Endpoint: GET /accounts
   - Description: Retrieves a list of all user accounts.
   - Query Parameters:
     - `page` (integer, optional, default: 1): The page number for pagination.
     - `limit` (integer, optional, default: 20): The maximum number of accounts to return per page.
   - Responses:
     - 200 OK: Successfully retrieved the list of accounts.
     - 401 Unauthorized: Authentication is required to access this resource.
     - 403 Forbidden: You do not have permission to access the accounts.
     - 500 Internal Server Error: An unexpected error occurred on the server.

5. Delete an Account
   - Endpoint: DELETE /accounts/{accountId}
   - Description: Deletes a specific user account.
   - Path Parameters:
     - `accountId` (string, required): The unique identifier of the account to be deleted.
   - Responses:
     - 204 No Content: Successfully deleted the account.
     - 401 Unauthorized: Authentication is required to access this resource.
     - 403 Forbidden: You do not have permission to delete the account.
     - 404 Not Found: The specified account does not exist.
     - 500 Internal Server Error: An unexpected error occurred on the server.

Rate Limit
The Accounts Service has a rate limit of 100 requests per minute per IP address. If the rate limit is exceeded, the following response will be returned:

- 429 Too Many Requests: The rate limit has been exceeded. Please try again later.

Error Handling
The Accounts Service follows a consistent error response format for all API endpoints. The error response will include the following fields:

- `error_code` (string): A unique error code that identifies the specific error.
- `error_message` (string): A human-readable error message that provides more information about the error.
- `error_details` (object, optional): Additional details about the error, if applicable.

Example error response:

```json
{
  "error_code": "INVALID_REQUEST",
  "error_message": "The request body is invalid or missing required parameters.",
  "error_details": {
    "missing_fields": ["username", "email"]
  }
}
```
