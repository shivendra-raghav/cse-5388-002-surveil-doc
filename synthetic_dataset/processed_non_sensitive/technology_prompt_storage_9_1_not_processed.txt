Oracle Cloud Storage Documentation

Introduction

Oracle Cloud Storage is a highly scalable and secure object storage service offered by Oracle Cloud Infrastructure (OCI). This service provides a durable and cost-effective solution for storing and managing large amounts of unstructured data. It is designed to offer reliable and fast data access with built-in redundancy and security features to protect your data.

This documentation will provide an overview of the Oracle Cloud Storage service, including details on how to access and manage your storage resources, configure data archival, and understand the available storage tiers.

Oracle Cloud Storage Access Details

To access the Oracle Cloud Storage service, you will need to have an active Oracle Cloud account. Once you have an account, you can follow these steps to get started:

1. Log in to the Oracle Cloud Console (https://console.us-ashburn-1.oraclecloud.com/) using your account credentials.

2. In the Console, navigate to the "Storage" section and select "Object Storage".

3. In the Object Storage dashboard, you can create a new storage bucket or manage your existing buckets. To create a new bucket, click the "Create Bucket" button and follow the on-screen instructions to configure your bucket settings.

4. To access your storage buckets programmatically, you can use the Oracle Cloud Infrastructure (OCI) SDK or the Command Line Interface (CLI). The OCI SDK is available for various programming languages, including Python, Java, and Node.js. To set up the SDK or CLI, follow the instructions provided in the OCI documentation: https://docs.cloud.oracle.com/en-us/iaas/Content/API/Concepts/sdks.htm

5. When accessing the Oracle Cloud Storage service using the SDK or CLI, you will need to provide your account credentials, which include your user ID, tenancy ID, and an API signing key. Detailed instructions on generating and using these credentials can be found in the OCI documentation: https://docs.cloud.oracle.com/en-us/iaas/Content/API/Concepts/apisigningkey.htm

6. Once you have your credentials set up, you can use the OCI SDK or CLI to perform various operations on your storage buckets, such as uploading, downloading, and managing objects.

Data Archival

Oracle Cloud Storage provides a comprehensive data archival solution to help you manage your long-term data retention requirements. The service offers two main archival options:

1. **Archived Storage**: Archived Storage is designed for infrequently accessed data that requires long-term retention. This storage tier offers the lowest cost per gigabyte, making it ideal for data that is not accessed frequently but needs to be kept for compliance or historical purposes. Data stored in Archived Storage can be retrieved, but the retrieval process may take several hours.

2. **Object Lifecycle Management**: The Object Lifecycle Management feature allows you to automatically transition your data between different storage tiers based on predefined policies. For example, you can configure a policy to automatically move data from the Standard tier to the Archived tier after a certain period of time. This helps optimize your storage costs by ensuring that your data is stored in the most appropriate and cost-effective tier.

To configure data archival for your storage buckets, follow these steps:

1. In the Oracle Cloud Console, navigate to the "Object Storage" section and select the bucket you want to manage.

2. Click on the "Lifecycle" tab and then click the "Create Rule" button.

3. Define your lifecycle rule, including the conditions for transitioning data to the Archived Storage tier and the desired retention period.

4. Review and save your lifecycle rule, and it will automatically be applied to your storage bucket.

Storage Tiers

Oracle Cloud Storage offers several storage tiers to meet your diverse data storage needs. The available tiers are:

1. **Standard Storage**: Standard Storage is the default and most versatile storage tier, designed for frequently accessed data. It provides low-latency and high-throughput performance, making it suitable for a wide range of use cases, such as web applications, mobile apps, and content delivery.

2. **Infrequent Access Storage**: Infrequent Access Storage is optimized for data that is accessed less frequently than data stored in the Standard tier. It offers similar performance characteristics to Standard Storage but at a lower cost per gigabyte. This tier is ideal for data that is accessed occasionally, such as backups, archives, and logs.

3. **Archived Storage**: As mentioned earlier, Archived Storage is designed for infrequently accessed data that requires long-term retention. This tier offers the lowest cost per gigabyte but has a higher latency for data retrieval, as the data is stored on slower, more cost-effective storage media.

When choosing a storage tier, consider the following factors:

- **Access Frequency**: Determine how often you need to access the data. Data that is accessed frequently should be stored in the Standard or Infrequent Access tiers, while data that is rarely accessed can be stored in the Archived tier.

- **Retrieval Time**: Understand the acceptable retrieval time for your data. Standard and Infrequent Access storage offer faster retrieval times, while Archived Storage may take several hours to retrieve data.

- **Cost**: Evaluate the cost implications of each storage tier. Archived Storage is the most cost-effective option, while Standard Storage is the most expensive.

- **Compliance and Regulatory Requirements**: If you have specific compliance or regulatory requirements, ensure that the storage tier you choose meets those requirements.

To manage your storage tiers, you can use the Oracle Cloud Console or the OCI SDK/CLI. In the Console, you can view the usage and costs for each storage tier, as well as configure the Object Lifecycle Management feature to automatically transition data between tiers.

Conclusion

Oracle Cloud Storage provides a robust and scalable object storage service that can meet the diverse data storage needs of your organization. By understanding the access details, data archival options, and available storage tiers, you can optimize your storage costs and ensure the long-term durability and availability of your data.
